# Submission preparation

1. The independently supplied foundation is a mixed-origin integration frozen on October 28, 2026, containing earlier source and event-era adaptations. It is excluded from new-work claims and is not a pre-event revision. Its manifest hash and every foundation file's bytes and executable status must match the supplied inventory. No public redistribution license is implied.
2. `scripts/submission/prepare.py prepare` compares each inventoried file in a specified current tree with the immutable foundation and records text changes as line-copy, line-skip and readable UTF-8 additions. Deleted foundation lines are not included in the candidate. Every new candidate file requires an explicit `--new-file` argument; unknown untracked files are not swept in. Dot-prefixed paths are rejected except `.env.example`; private and dependency directories are rejected. Changed non-UTF-8 files and missing baseline files fail rather than being silently copied. The maintainer must review additions and select only authorized event work; the tool cannot determine authorship or rights.
3. Preparation creates a separate foundation ZIP and a fresh candidate directory. The candidate includes the foundation manifest, changes, explicitly selected new files, reconstruction script, review inventory and instructions. The foundation ZIP must be supplied independently. Judge access, publication, and licensing are not established by preparation.
4. `reconstruct` refuses an existing output, checks inventory and archive members, rejects duplicate, traversal, symlink, encrypted, unexpected, oversized or mismatched members, applies changes in a temporary directory and verifies every final file's hash, size and executable status. It never reads application data or changes a budget. A failed reconstruction must not leave a successful output.
5. Verify with `python3 -m unittest discover -s tests/submission -v`. Before delivery, also reconstruct the actual intended tree, compare its complete inventoried bytes and modes, review the generated candidate for private content and origin, and run applicable application checks and Chrome verification from the reconstructed tree. Fixture-only verification does not prove live service access.
