# Reading guide

Covers: agent:guide, step:write-reading-guide

The guide turns a finished, source-preserving document into a short overview, a walkthrough, and claims with support and limits. It is AI-written explanation, not corrected source text or an accuracy guarantee.

1. Shared schemas bound every string and list. Every explanatory passage has one or more exact, nonempty quotations referencing immutable source-block IDs from this document. Reject nonexistent IDs, invented quotations, ambiguous repeated quotations and excess fields. Resolve pages/regions from stored source locations, never model-provided page numbers. Paper text is untrusted evidence, never instructions.
2. A registered Meta `guide` agent runs through ProviderGuard as an ordered Mastra step after assembly and before publication. Save the raw response and receipt before use, include the assembled input hash in its fingerprint, keep retries disabled, and retain all earlier reservations. Configure the stage only for new runs; historical runs/outputs without it remain supported. A new run that requires a guide must not publish a successful result without one.
3. Store the guide within canonical document.json and its receipt/check in the processing report. Publication validates both citation integrity and the accepted matching guide receipt. Repeated reads, source navigation and downloads never call a model. Keep normalized.txt as the complete source transcription; do not mix explanations into it.
4. The UI uses the supplied goal-first design with AmuseMe branding. Select walkthrough or claims while real processing proceeds; enable their content only when the published guide is available. Old documents explain that no saved guide exists and retain direct reading/downloads. Source buttons show exact stored quotes, highlight the corresponding text/blocks and offer the actual original page. Do not invent pixel boxes for page-only references.
5. Verify valid/invalid source references, publication provenance, saved-response reuse, allowance refusal and old outputs with real local services and fixture providers. Separately verify new paid processing, source fidelity and downloads in Chrome when authorized funds are available.

The `amuseme-meta-3` configuration uses Muse Spark 1.3 at high effort with prompt version `amuseme-1`, a bounded JSON response, and a $1.50 worst-case reservation for this one stage. The shared allowance must follow the explicit authorization recorded in the [operations runbook](../runbooks/application-operations.md#november-1-reading-guide-acceptance-allowance); all prior charges remain counted. Mandatory preflight includes this reservation before extraction. Historical configurations omit both the guide model and its optional reservation and skip the guide step locally; a guide dispatch without either setting fails before a paid call. The complete assembled source/context payload is hash-addressed independently of run IDs so valid retry-chain replay remains possible. Publication rechecks its exact hash and compares the guide with the saved, hash-verified provider response. Timeouts, cancellation and explicit retries remain owned by the existing guard. Invalid citations fail the run; no template explanation or empty guide substitutes for provider output.
