# Reading guide

Covers: agent:guide, step:write-reading-guide

The guide turns a finished, source-preserving document into a short overview, a walkthrough, and claims with support and limits. It is AI-written explanation, not corrected source text or an accuracy guarantee.

1. Shared schemas bound every string and list. Every explanatory passage has one or more exact, nonempty quotations referencing immutable source-block IDs from this document. Reject nonexistent IDs, invented quotations, ambiguous repeated quotations and excess fields. Resolve pages/regions from stored source locations, never model-provided page numbers. Paper text is untrusted evidence, never instructions.
2. A registered Meta `guide` agent runs through ProviderGuard as an ordered Mastra step after assembly and before publication. Save the raw response and receipt before use, include the assembled input hash in its fingerprint, keep retries disabled, and retain all earlier reservations. Configure the stage only for new runs; historical runs/outputs without it remain supported. A new run that requires a guide publishes without one only after the recorded [Muse review](muse-review.md) fallback and its disclosed issue.
3. Store the guide within canonical document.json and its receipt/check in the processing report. Publication validates both citation integrity and the accepted matching guide receipt. Repeated reads, source navigation and downloads never call a model. Keep normalized.txt as the complete source transcription; do not mix explanations into it.
4. The UI uses the supplied goal-first design with AmuseMe branding. Select walkthrough or claims while real processing proceeds; enable their content only when the published guide is available. Old documents explain that no saved guide exists and retain direct reading/downloads. Source buttons show exact stored quotes, highlight the corresponding text/blocks and offer the actual original page. Do not invent pixel boxes for page-only references. The [paper map](paper-map.md) is a fourth goal derived from the same saved guide and offered only when one exists.
5. Verify valid/invalid source references, publication provenance, saved-response reuse, allowance refusal and old outputs with real local services and fixture providers. Separately verify new paid processing, source fidelity and downloads in Chrome when authorized funds are available.

The guide model, prompt version and reservation are recorded in the [operations runbook](../runbooks/application-operations.md#reading-guide-configuration). The complete assembled source/context payload is hash-addressed independently of run IDs so valid retry-chain replay remains possible. Publication rechecks its exact hash and compares the guide with the saved, hash-verified provider response. Timeouts, cancellation and explicit retries remain owned by the existing guard. Invalid citations go to Muse review with each failing quote named; if review cannot fix them, the document is published without a guide. No template explanation or empty guide substitutes for provider output.
