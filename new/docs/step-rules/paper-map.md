# Paper map

The paper map shows how a saved [reading guide](reading-guide.md) connects to the paper. Readers select a step, claim, limit or cited passage, see its connections and open the exact source passage. It is a view of the guide's citations, not a measured graph or a new analysis.

1. Derive the map in the browser with the pure `paperMap` function from `canonical.guide` and the stored source blocks. Add no model call, Hindsight service, route, schema or stored artifact. A document without a saved guide offers no map; a map route for it shows the existing no-guide choices.
2. Nodes are each walkthrough step, each claim, each limit and each distinct cited source block. The overview is not a node. A passage node lists every distinct quotation cited from its block and takes its page label from stored locations, never from guide text. Order nodes as steps, claims each followed by their limits, then passages by first page and reading order.
3. Edges are typed: step to next step (reading order), step or limit to passage (cites), claim to passage (cites, or supporting evidence with the saved strength), and claim to limit. When a claim both states and is supported by the same block, keep the supporting-evidence edge. Shared passages are the only links between steps and claims.
4. Lay out three fixed columns: walkthrough, cited passages and claims with nested limits. The layout is a pure function of the map, measured width and root font size; node heights fit their clamped text at any font size. Stack passages from the top in page order. Place each step, and each claim with its limits, at the mean height of the passages it cites, then push groups down top to bottom so they keep reading order with a fixed gap. Groups with no cited passage follow the group above; a column with none starts at the top. Reading-order curves stay within the margin left of the step column. Below 1000 CSS pixels, replace the drawing with grouped lists that open the same selection panel. Disclose that connections come from the guide's citations, not measured relationships.
5. Give each line type one style and name each in the legend: dashed grey for reading order, solid grey for a citation, solid green for supporting evidence with strong, partial and limited support shown by decreasing weight, and amber brackets for limits. Only reading order is dashed. Every resting line keeps at least 3:1 contrast with the map panel in both themes, so weight, not transparency, carries strength; only the hover/selection highlight dims unrelated lines. The map uses the standard reader page width, like every other page.
6. Store only the selected node number in the URL as `mode=map&node=N`, with `N` from 1 to 999 and the existing `source`, `view` and `p` parameters. Never put node text or quotations in the URL. Unknown node numbers show the map without a selection.
7. Selecting a node by click, tap, Enter or Space shows its title, explanation and connections. Arrow keys move focus within a column and to the nearest node in the next column; only one node is in the tab order. Hover and focus highlight the active node's edges. Source actions reuse the guide's evidence drawer, highlighting the exact stored quotation and offering the original page.
8. Tests cover derivation counts, passage deduplication, edge types, page ordering, the no-guide case, deterministic barycenter placement, curve bounds, legend coverage, keyboard neighbors, route validation and source opening. Verify both themes at desktop and phone widths in Chrome.

`src/app/map/layout.ts` adapts MIT-licensed Hindsight curve geometry; keep `src/app/map/LICENSE` and `NOTICE.md` with it.
