# Meta page extraction

Covers: agent:extraction

1. Normal uploads use Spark 1.3/high through the registered extraction agent, ProviderGuard, saved response envelopes and zero automatic retries. One request per physical page runs serially. The host supplies the verified rendered PNG, actual page number/count and dimensions, without another model extraction or an answer key. Version 1 remains the bounded single-page trial contract for historical response validation.
2. Version 2 returns complete/incomplete coverage, an explicit blank flag, ordered literal blocks and figure proposals. A blank page has no blocks or figures. Nonblank pages retain meaningful content, furniture, code, equations, references, notes and literal HTML tables. Both version converters preserve provider-classified `code` as the supported code kind without changing its content, format or source locations. Only genuinely unclassified non-furniture content receives the existing located `unclassified-content` warning; explicit furniture remains retained under its existing sidecar rules. Incomplete responses, wrong pages, invalid figure/caption references, duplicate ownership and boxes outside the supplied page fail before acceptance. Model coverage is not proof of fidelity.
3. The host assigns stable page/block/figure IDs and contiguous document reading order. Model figure boxes are source proposals in rendered-page pixels, never trusted paths or verified semantic boundaries. Round left/top down and right/bottom up once, require positive in-page integer bounds, then create the exact pixel region from the hash-verified source-page PNG. Export provenance binds the PDF hash, page ID/number, page image hash/dimensions, integer crop box, actual output dimensions and crop recipe. This is a rendered source-page region, never a native embedded-image claim. Missing regions and bounded crop-runtime failures remain unavailable figures with located issues; source-integrity or structural failures stop the run.
4. Preserve original captions once, caption/source locations and all figure records. New available Meta figures require rendered-region provenance. Old figure assets without provenance remain historical unspecified assets. Description quality and crop selection remain unvalidated semantic claims.
5. Save each raw response before application. New extraction checkpoints retain every per-page receipt in page order; legacy single-receipt checkpoints remain readable, while ambiguous checkpoint forms fail. Restart reuses identical accepted pages without another generation. Invalid responses remain saved and no partial revision publishes. Page coverage and accepted extraction receipts must match every physical page.
6. Runtime generation is Meta-only. Reject stale non-Meta run configurations before preflight, reservation or dispatch, including direct prepared-ticket dispatch and resumed later workflow steps. Historical schema reads and spending records remain unchanged. Configuration requires the Meta credential and original budget, not a MinerU service. Original reservations, ceilings and unknown charges are retained. Before any preflight, mandatory extraction/page-check/heading reservations must fit the saved per-document cap; figure costs remain subject to the guard after discovery.
7. The experimental CLI retains its explicit one-page version-1 trial and original-ledger checks. No automatic paid retry or budget increase is authorized. Offline fixtures cover multipage/blank content, tables/figures, malformed boundaries, second-page failure/replay, legacy reads and denied stale MinerU work. Live quality and Chrome acceptance require separate authorized evidence.
