# Meta provider

Covers: agent:page-check, agent:headings, agent:figures

Each stage agent has a registered Muse reviewer agent, `<stage>-review`, with the same permit, transport and limits; see [Muse review](muse-review.md). The adapter selects the reviewer when the request names the reviewer schema; the receipt keeps the stage's model configuration. The reviewer brief follows the selected stage prompt version. `figures-crop-review` is selected only for a `figures` receipt with task `figure-crop` whose request names the crop-review schema and carries one of its published prompt versions exactly; it uses the figures model configuration, effort and output limit. A run configured with page-check `amuseme-2` keeps that prompt and schema.

1. The registered agents accept only an adapter-issued opaque permission tied to the current stage and dispatched `ProviderCall`. A pure Effect schema checks identity. The pinned Zod wrapper exists only for Mastra's public context-schema and Studio serializer. Metadata inspection needs no credential or permission.
2. `makeMetaAgentBoundary` creates agents and their private permission map. `makeAdapter` captures the supplied Effect HTTP context with `Effect.runPromiseWith`. Promise conversion occurs only in model-method SDK callbacks and around `Agent.generate`. No second runtime, direct global fetch, durable executor, or provider retry exists.
3. The canonical request is the guard's complete `intent.request`. It contains Spark 1.3, the exact stage instructions and user text/images, strict JSON Schema, effort, and output ceiling. Page checking, figures and the reading guide use high effort; headings use medium. The actual normalized model prompt and settings must match before transport. Mastra's sole `{mastra: {createdAt: number}}` message metadata is permitted and is not sent. Agent options do not grant document text any tools or network authority.
4. The adapter calls the registered agent with one step, no tools, no memory, no scorers, and zero model/processor retries. The permission is consumed immediately before HTTP execution and revoked on every exit. All model methods share it. The existing guard owns explicit paid retries and saved-response reuse.
5. HTTP sends to the fixed Meta Chat Completions endpoint with bearer credentials only in the authorization header. The transport enforces the guard deadline, cancellation, output limit, and a raw-body cap that leaves room for base64 and envelope metadata. A truncated prefix is marked incomplete. Transport errors without a complete response remain unknown completion. Cancellation revokes permission, aborts generation, and awaits both the generation and every pending model transport's cleanup before returning to the guard. No redirect-following client belongs in this boundary.
6. Save a private versioned JSON envelope containing status, allowlisted request ID, base64 body, and completeness. The guard saves it before stage validation, including complete malformed JSON and error responses. The model result exposes only assistant text and measured token counts. It excludes raw bodies, headers, credentials, and reasoning. A remote ID is durably recorded when observed; callback failure prevents successful delivery.
7. Validation rejects incomplete bodies, non-success status, invalid provider JSON, wrong model, refusal, tool output, non-stop completion, and invalid assistant JSON. Complete canonical-base64 envelopes for HTTP429/502/503/504 return provider-failed for the explicit retry owner; no automatic send occurs, and saved bytes remain available. Other invalid outputs remain invalid-provider-response. The injected stage validator checks its schema and semantic constraints against source artifacts. Missing usage/cost stays unavailable, and reservations remain until measured charges are known.
8. Tests use real registered Mastra agents, the SQLite guard/store, and fake HTTP. They prove exact request bytes, saved malformed responses, cancellation, one send under failure, invalid permission denial, and zero-send replay. The outer gateway owns generic Studio execution denial; the manager owns its integration tests and Chrome inspection. No offline test establishes provider quality or paid-call behavior.
9. The non-generating token-count preflight has a 60-second deadline, a 4096-byte response cap, and no retries. Transient HTTP, network, and timeout failures are provider-failed with no generation submitted; mandatory stages may be retried only through the existing explicit retry owner. Rejected credentials, malformed counts, and oversized context retain distinct configuration, validation, and limit failures. Never turn them into unknown paid completion or silently truncate context.

The registered extraction agent supports the immutable version-1 trial and version-2 document page schema using their exact saved prompt versions. Registered agent instructions are selected only from a validated guarded binding. Figure prompt version amuseme-2 describes source images without claiming rendered regions are native; the historical version-1 template remains available.
