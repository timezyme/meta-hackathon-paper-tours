# Document UI

1. The dashboard lists the reader's own documents, then a read-only **Examples** section from the list's optional `examples`. Example rows, readers and guides hide delete, retry and rating controls; downloads stay available. When the list carries `upload.allowance`, the upload box shows uploads left and disables choosing once none remain; the server's refusal message is shown as-is. The dashboard decodes the shared document-list response, including server-owned PDF byte/page limits, admission availability, and live/fixture mode. Loading and failed reads never become an empty successful library. English-language scope is stated before upload; language detection is not claimed.
2. Choose/drop accepts exactly one nonempty file within the advertised byte limit. MIME and filename checks are hints; the server validates actual PDF contents and page count. One pending upload disables chooser/drop and duplicate submission. A multipart POST contains only `file` and an idempotency-key header. No upload or processing mutation retries automatically.
3. One App-owned React state retains the File and Effect-Random 128-bit key across route changes, scoped to the authenticated user. Unmount interrupts HTTP and marks pending work uncertain. On uncertain completion, reload the library before permitting explicit retry with the same file/key or explicit discard. Full-page reload loses local file memory but reads the persisted library before enabling a new upload. Sign-out clears the attempt.
4. List/detail/status/acceptance and safe API errors use shared Schema contracts. HTTP 401 triggers session revalidation. Other refusal, transport, timeout, malformed-response, missing/expired/foreign document errors remain visible. A failed upload never creates a successful card locally.
5. Cards and details show only saved filename, page count, bytes, expiry, and actual run state. Effect polls queued/running status sequentially every three seconds after the previous read completes; no overlapping requests, global timers, or mutation resubmission. Unmount interrupts the complete scope. A polling failure stops polling, preserves the last result with an explicit stale-status message, and offers a manual read retry.
6. Original download uses the owner-checked endpoint. Cards with a published revision offer Open document and Download text through the shared owner/revision output URL; retain both when a later run fails. Cards without published output have no text-download link. The reader uses the current saved revision and follows [Document reader](document-reader.md). Fixture admission is visibly labeled and produces only real queued database records; it does not advance fake progress or invoke providers.
7. Reuse the approved Sky header, olive palette, Geist type, restrained document cards, dark default, and saved light choice. Verify chooser/drop, multiple/empty/oversized input, server rejection, pending/uncertain/key retention, actual status polling, detail/back/original, two-user isolation, and all four viewport widths in Chrome.

React callbacks are the runtime boundary. `src/app/client/documents.ts` owns HTTP, FormData creation, request scopes, deadlines, Effect randomness, and polling. Browser code makes no direct provider calls. The isolated port-4182 fixture injects admission configuration through the server constructor. Production admission is enabled only by complete live provider/policy configuration; otherwise the UI displays the server's disabled reason.
