# Page checking

1. Input is the immutable Extraction, one existing page ID, and its already hash-verified PNG bytes. The manager owns artifact reads, hashes, ProviderGuard, receipts, retries, cancellation, deadlines, and Mastra execution. These modules perform no I/O.
2. Send the whole current page and the preceding page's suffix starting at its third-last prose paragraph (or all available prose), including intervening blocks. The previous page is context only. The prompt asks the model to fix only a table's words, symbols and line breaks and keep every number, row, column and cell as sent. Code keeps table fixes exactly as returned, without comparing source content or restoring heading marks. Tables retain their source format, which can be HTML or text. Figures cannot receive fixes; nonempty text cannot be deleted. The original extraction is never mutated.
3. Spark 1.3 uses high reasoning and the shared PageCheck schema, converted with public Effect JSON Schema APIs. Validate IDs, page membership, duplicate edits, furniture classifications, consecutive prose join endpoints (allowing only classified page furniture, including accepted page-check furniture, across the next page boundary), one-block replacements, and complete checked-page coverage. Preserve heading marks until heading classification.
4. CorrectedText retains source scope, copied blocks, proposed joins, changed IDs, and CheckedPage records. Joins remain proposals until headings resolve; retained headings cannot be joined. Only persisted, accepted responses may be passed to application functions by the workflow.
5. Request admission checks a byte ceiling and the 1,048,576-token context ceiling, reserving output, framing, and an explicit caller-supplied image-token upper bound. UTF-8 text bytes are a conservative text allowance, not an exact tokenizer. The manager must supply a defensible image allowance or measured count. Never truncate. Failure is typed and occurs before dispatch.
6. Saved artifacts are the source extraction, guarded raw response, receipt, CheckedPage, and corrected representation. A rejected answer goes to [Muse review](muse-review.md); the page check also rejects a fix or join that an earlier page's check already used. If review cannot correct it, the page keeps only the proposals that pass every check on their own (at worst none), the CheckedPage records the reviewed attempt, and the report discloses the fallback. Page checking is not proof of error-free output.

7. Page-check prompt version `amuseme-2` changes the request identity. Existing saved responses retain their original version and are never relabeled for live reuse. Identical version-2 requests reuse validated saved responses through the existing guard. The reader retains the historical version-1 public prompt. Synthetic version-keyed fixtures use the new version without changing their answers.
8. Tables and figures never join prose. Text-format tables are one literal block; their # characters never introduce headings. Whole HTML tables remain atomic for the existing heading-boundary check. Literal line breaks and HTML cell breaks survive assembly and export. The report records changed block IDs, not changed words, so table tags are not tokenized as words.
9. Page-check prompt version `amuseme-3` adds `furniture: [{blockId, role}]` to the answer (strict schema; role `header`, `footer` or `page_number`). The check may classify blocks on the current page only, and the host accepts a classification only when all of these hold: the block is a paragraph, heading, note or unclassified block; its text without a heading mark is at most 120 characters and 16 words; a `page_number` looks like a page number; a `header` or `footer` repeats on another page (letters only, case-folded, digits and punctuation ignored, at least three letters), looks like a page number, or has a box location in the top or bottom 15% of the page; a header sits before all of the page's non-furniture content and a footer after it (a page number either). A block that is already furniture with the same role is a no-op; another role is rejected. At most 12 classifications per page.
10. Accepted furniture is applied in page order on top of the original extraction: the block becomes an `unclassified` block with a `pageFurniture` entry, exactly like extractor furniture. Join validation (`canJoinSources`), heading candidates, assembly, the published extraction and canonical document and publication validation all use this checked extraction, so a join across an accepted running head is kept and the furniture leaves the reading text. Source text is never changed, so exact-quote guarantees are unchanged. `processing-report.json` lists page-check furniture under optional `pageCheckFurniture`. The Muse review fallback keeps furniture that passes on its own, then fixes and joins.
11. Runs configured with page-check `amuseme-2` keep its prompt, schema and requests exactly, so their saved answers still decode and replay; answers without `furniture` decode as no furniture. Only new configurations use `amuseme-3`.

## Known gap

Nothing in code stops a table fix from changing a number, row or cell. The prompt asks the model to preserve them, but a wrong change reaches the reader. One-block validation detects heading boundaries and treats whole HTML tables as atomic; it does not prove one well-formed HTML table.
