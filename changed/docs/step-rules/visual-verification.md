# Manual visual fixture

1. `tests/manual/visual-server.ts` serves the current built app bytes and synthetic reader data on loopback port 4187 or 4193. It reads only the selected app directory. It imports shared contracts and maintained reader fixtures, never application startup, storage, credentials, or provider adapters.
2. `/qa` selects a validated scenario and clears bounded in-memory request history. Fake sign-in accepts dummy input without reading or logging credentials. Retry, rating, and terminal deletion change only fixture memory. Restart resets all state. The fixture is not authentication, persistence, PDF inspection, or live-processing evidence.
3. Require the exact loopback Host for every request and exact Origin for mutations. Serve only preloaded, named assets and declared routes, with no filesystem or network passthrough. Fingerprint index and JavaScript/CSS bytes with SHA-256. The process owns its listener through an Effect scope and releases it on exit.
4. Upload scenarios return deterministic 429, 409, or 503 refusals without reading, saving, or admitting the request body. Other scenarios disable admission. Original-PDF and ZIP routes are unavailable. Canonical JSON, report, text, and tiny synthetic images support visual checks only.
5. The manager checks the built fingerprints against the serving candidate, opens `/qa` and the actual reader in a browser, and records the scenario, browser engine and observed behavior. Use Chrome through CUA accessibility/native controls or supported Chrome DevTools commands when attachable; otherwise use the cmux built-in browser (WebKit) per `.agents/skills/browser-verify/SKILL.md`. Never use Playwright CLI, MCP, APIs, or `cmux browser repl`. Native OS drop, clipboard-permission failures, and organizational download blocks remain separate driver limits. Do not bypass browser policies. Tests cover real HTTP boundaries, scenario transitions, retry identity, and refusal behavior without inference or live data.
