# Private PDF page rendering

Covers: service:pdf-renderer

1. `PdfRenderer.render` consumes an already admitted immutable PDF's absolute private path, byte count, SHA-256, page count, and an existing private run directory. Reopen the source without following its final symlink, require a regular owner-private file, verify the actual size and hash, and render from that bounded byte snapshot. Mismatches never produce accepted pages.
2. By default produce every physical page in order, including blank pages, as `pages/page-001.png` and subsequent numbered names. An optional validated `pageNumber` renders only that physical page and retains its original number in the output path; reject selections outside the admitted page count. Create an exclusive owner-private `pages` directory and refuse existing output. One Effect resource scope kills the process group on cancellation or failure before removing only this newly owned directory. Completed output stays private for the caller to persist or remove with the run.
3. Target 300 DPI, reducing the uniform scale to at most 3,300 pixels per side. Bound each page to 10,890,000 pixels, the document to 544,500,000 rendered pixels, each encoded PNG to 32 MiB and all PNGs to 100 MiB. Render one page at a time. Return each actual pixel size, scaling DPI, oriented width/height in PDF points, physical PDF rotation, PNG byte count and SHA-256. PNG resolution metadata rounds the scaling DPI to the nearest integer; pixel dimensions round outward as PyMuPDF requires.
4. `physicalRotation` is the PDF's metadata rotation already applied by PyMuPDF. It is never the converter's relative MinerU-to-PNG rotation. The caller binds that separate coordinate frame after inspecting actual MinerU layout dimensions. Matching dimensions normally imply relative zero; dimensions alone do not establish a square page's rotation or a 180-degree transform. This renderer does not guess a relative transform.
5. Use locally provisioned Python 3.14.5 and PyMuPDF 1.28.2 with isolated mode, an empty environment, no runtime install, and no network or provider calls. Preserve the admission size, geometry, object and embedded-image guards. Rendering has its own 60-second CPU and 120-second wall ceilings, 1 GiB memory threshold, and bounded 64 KiB stdout/stderr. Linux additionally enforces address space; the inherited RSS supervisor can briefly overshoot between 50 ms samples and is not a security sandbox.
6. Expected errors use safe typed codes. Never return private paths, source contents or subprocess stderr in errors. There are no retries. Output metadata must pass Effect Schema decoding and match the requested ordered page count and canonical paths. Flush and sync each PNG before publishing successful metadata.
7. This adaptation uses the page rasterization and Effect subprocess patterns from `src/paper/pdf.ts` in the normalization source at revision `abc31fb7745ecb973bbf0261a9e82f52ea8f17ad`, file SHA-256 `3425d792c75a3b96ef15ceac08fd9064a9badb1b8387a69438ec460830a379a4`. It does not copy photo conversion, figure cropping or discovery. Existing PyMuPDF license notices and packaging obligations in `python/README.md` apply.
8. Actual generated-PDF tests verify rotated and square pages, scan pixels, maximum side scaling, reopened PNG dimensions, SHA-256, private file modes, wrong hashes/counts, unsafe paths, output collision, stream bounds, cancellation and cleanup. The manager separately verifies coordinate binding and downstream image use in the integrated workflow.

9. PdfRenderer.crop accepts only a private verified page PNG and an integer in-page box. Decode the PNG only after its bytes/hash match the page manifest; require actual dimensions to match. Crop exact existing pixels using PyMuPDF without interpolation, save exclusive private output, bound subprocess/resources/bytes and clean newly owned output on failure. Reopen and verify resulting dimensions/hash. Crop geometry is structural proof only, not figure-selection fidelity.
