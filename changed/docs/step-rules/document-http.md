# Document HTTP routes

Covers: route:POST:/api/documents, route:GET:/api/documents, route:GET:/api/documents/:documentId, route:GET:/api/documents/:documentId/status, route:GET:/api/documents/:documentId/original, route:GET:/api/documents/:documentId/preview, route:DELETE:/api/documents/:documentId, route:POST:/api/documents/:documentId/retry

The preview route requires a valid `page` query within the document and returns a PNG rendered from that original page using the bounded existing PDF renderer. It renders the stored original in place after the same owner and expiry checks as original download; the renderer verifies its size, hash and private ownership, and access is rechecked after rendering. One preview render may run at a time; a competing request gets 429. A scoped private `preview-` directory holds only the rendered page and is removed on success, failure or cancellation; preview rendering has a 20-second deadline and makes no model calls. Keep no-store and frame denial. The original download remains unchanged. UI failures show an explicit retry and original-download link.

1. `makeAmuseMe` registers only these implemented product routes through the public Mastra API. The gateway allows these exact methods and safe path shapes to authenticated users. Each document handler independently resolves the session and derives ownership from it. Another owner's document returns 404. Client owner fields and roles grant no access.
2. List, detail, status, acceptance, and error responses use shared schemas. The list includes `PdfLimits` and admission availability. Production stays disabled with `mode: live` until the real pipeline is configured. Only an explicitly injected `fixture` constructor permits test admission, with `mode: fixture` disclosed in the list. There is no fixture environment switch or automatic provider fallback.
3. POST requires the configured Origin, rejects cross-site Fetch Metadata, and accepts exactly one multipart `file` and a valid idempotency key. No other fields are accepted. The body reader limits actual bytes to the PDF ceiling plus 64 KiB multipart overhead and has a 20-second deadline. The separate PDF ceiling remains 50 MiB. MIME, extension, Content-Length, and client page/owner fields are not trusted. Validate the platform parser's decoded display filename, including path separators, length, and control characters. The pinned Node parser preserves tested path separators, which this schema rejects. If a future parser returns a normalized basename, it remains display metadata. Store only under opaque server-generated IDs; no filename becomes a filesystem path.
4. One request may inspect an upload at a time. A competing intake receives 429 rather than waiting in an unbounded queue. Disabled admission returns 503 before body parsing or persistence. Write the accepted body to a mode-0600 file inside a scoped mode-0700 directory, run the real `PdfInspector`, then call `DocumentStore.admit` with its page count and the server's configuration snapshot.
5. The scope removes temporary files on success, rejection, timeout, and cancellation. Before the listener opens, storage startup removes crash leftovers in the generated upload namespace alongside render/archive/blob leftovers, as specified in [retention](retention.md). Storage owns hashing, durable source publication, document/run records, admission idempotency, and the dispatch intent. Return 202 only after that commit. A disconnect cannot undo committed work; retrying its idempotency key returns the same IDs. No request callback invokes a provider or starts processing. Reads never create work.
6. Original downloads recheck server-owned access through storage and return the exact stored bytes with no-store, application/pdf, nosniff, and a safe attachment filename. Source paths never enter routes or responses. Later streamed exports remain separate work.
7. Map expected failures to the shared safe API code/status. Session or storage unavailability must not become an empty successful library. Malformed input, encrypted/blank PDFs, file/page/resource limits, queue bounds, and idempotency conflicts remain distinct. Propagate the HTTP cancellation signal through the ManagedRuntime and scoped body/inspection work. Do not automatically retry uploads.
8. Verify real HTTP requests against private SQLite and the actual PDF subprocess with two authenticated users. Cover byte equality, duplicate keys, conflicting submissions, restart after acceptance, foreign/expired ownership, forbidden methods/encodings, forged fields, unsafe names, PDF limits, cancellation, cleanup, storage failure, and disabled configuration. Manager Chrome acceptance covers the UI separately.
9. DELETE requires the same exact Origin and Fetch Metadata checks as upload, then delegates terminal-only authorization to `DocumentStore.delete`. Return empty 204 only after local removal succeeds. Repeated or expired deletes remain concealed with 404; queued/running work returns 409. Preserve live admission configuration and never interpret delete as provider cancellation.

10. Retry accepts only the expected previous run ID and repeated-work acknowledgment, with a separate idempotency header. Require same-origin authenticated ownership before decoding a bounded 1 KiB JSON body. The durable RunRecovery transaction rechecks latest state, budget, evidence and acknowledgment; the HTTP handler never dispatches or automatically repeats a provider call. A repeated identical request returns the same accepted IDs.
