# Application UI

The browser provides sign-in, the authenticated AmuseMe upload/dashboard, processing states, and the saved-output reader. The server owns session validity, roles, document authorization, admission, and processing.

1. `GET /api/session` is decoded with the shared `Session` schema. A 401 means signed out; transport, timeout, invalid-response, and service failures remain visible errors. The sign-in page reads `/auth/sign-in-options`. In password mode it posts only email/password to `/auth/sign-in/email`. In email mode it asks only for an email (and an access code when required), says "Enter your email to try AmuseMe", and posts to `/auth/sign-in/judge`; sign-out posts to `/auth/sign-out` and clears the UI only after server confirmation. No browser mutation retries, public registration, password recovery, or model calls exist.
2. `src/app/client/` owns Effect HTTP transport, browser history, and browser storage. The exact `effect/http` module uses `FetchHttpClient` with same-origin credentials, no caching, and rejected redirects. React lifecycle/event callbacks are runtime boundaries. They retain the Effect interruptor and cancel active requests on unmount. Authentication has a ten-second deadline; document and output requests have a 30-second deadline. Duplicate form submissions and concurrent sign-out are locked until completion.
3. Browser session state is checking, signed out, authenticated, or unavailable. Pathname changes and returning to a visible tab recheck the session; document-query changes retain the authenticated session and loaded output. Sign-in query changes still resolve the complete return path. Expired sessions show sign-in, preserving only `/` or a valid `/documents/:documentId` with bounded document-view parameters: page, mode, selected goal, step/claim number, paper-map node number, source number and source/reader view. Reject duplicate or unknown parameters, encoded values, external URLs, protocol-relative URLs, encoded separators and unknown paths. Never put document text or quotations in URLs or browser storage.
4. Only authenticated admins see the stock Studio link. Hiding it is a convenience, not authorization. An ordinary user's direct Studio page navigation receives the product shell with HTTP 403 and an “Administrator access required” page linking back to documents. API denials remain JSON. Documents and upload limits/availability come from decoded owner-scoped APIs. Enable one-PDF upload only when the current policy permits it; disclose Meta/MinerU processing, seven-day local retention, and terminal deletion. Keep pending, uncertain, rejected, empty, and unavailable states explicit. Queued/running documents refresh until terminal; published revisions open the [Document reader](document-reader.md). There is no fixture fallback in application code; explicitly configured fixture mode identifies itself.
5. Use the application’s local logo and matching favicon in `src/app/assets/`. Keep the same symbol geometry across the light and dark wordmarks and favicon. Preserve the Geist font and license, spacing, olive palette, dark default, and light alternative. Prototype previews mirror these brand assets. Persist only the theme in localStorage. A denied storage operation leaves the chosen theme usable for the visit and reports that persistence failed. Local storage never contains credentials or sessions.
6. Form labels, autocomplete, native email validation, visible focus, pending status, and associated error text are required. Error and session messages use live regions. Layout must fit 320, 390, 1024, and desktop widths in both themes without horizontal overflow. History Back/Forward must preserve route behavior. Sign-in input boundaries have at least 3:1 contrast in both themes, and mobile input text is at least 1rem. A ready route owner sets the page title and focuses its main landmark once per pathname transition, including history navigation through loading routes; checking/loading placeholders, query changes and background refreshes do not consume that focus request.
7. Tests exercise safe routing, HTTP status distinctions, schema rejection, single-attempt mutations, session expiry, real sign-in/out, theme persistence, upload eligibility, document states, and reader navigation. Real Chrome captures establish visual acceptance; intercepted browser responses establish only their named fixture behavior, not live processing. Keep terminal delete confirmation and explicit processing retry/idempotency behavior aligned with [Document reader](document-reader.md).

The library opens with a one-sentence statement of what AmuseMe does, the tagline and three numbered steps, then upload (when enabled) above the saved documents. It features one saved paper with its first page and title, and a guided paper offers a direct link to its first cited passage. Show guide links and counts only after validating the saved guide and its receipt. A paper without a guide opens in the full reader. Keep pending runs, upload admission, download options and deletion reachable. When uploads are disabled, keep saved papers available.

The browser-only `Effect.runSync` calls in `client/browser.ts` bridge synchronous DOM/history/localStorage APIs for React subscription and initialization. `Effect.runCallback` in `client/auth.ts` bridges cancellable HTTP programs to React callbacks. These narrow boundaries do not exempt presentation code from Effect rules.

After confirmed upload admission, navigate to its document. While queued/running, show actual saved progress beside goal selection (first on phones): a plain sentence from the saved stage and units ("Muse is checking page 2 of 4"), the ordered list of configured stages marked done, in progress or up next, and the time elapsed since the run's saved `startedAt`. No invented timers, estimates of remaining time or percentages. The only duration copy is a typical-duration note: processing usually takes several minutes, and the reader can leave the page while it runs. The upload area says short documents work best and usually take several minutes. Measure a live run before changing either note. A `limit-exceeded` run failure or upload refusal reads as a friendly too-long message that suggests a shorter PDF or excerpt; other failures keep the server's message. Readers may choose a walkthrough or claims while waiting, or open the exact original PDF immediately. Keep the selected goal/page in bounded URL state through publication. Guide buttons become available only after validated saved output arrives. Failures retain original access and expose only server-authorized explicit retries.
