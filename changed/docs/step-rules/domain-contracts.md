# Shared document contracts

Task 1B owns `src/domain/index.ts`, the public entry for schemas and pure cross-record validation. These contracts do no I/O, inference, retries, or orchestration. Consumers decode unknown data with Effect Schema and reject excess request properties. Pure validators run once when related records cross a persistence, provider, or publication boundary.

## Identity and source

`RunId` identifies one execution attempt. `ProviderAttemptId` identifies one provider dispatch within that run. Neither is a source hash, request fingerprint, or Mastra run ID. Storage must allocate a fresh run ID for explicit retries and enforce one immutable output revision per successful run.

Extraction freezes page and block IDs. Public page numbers start at one. A page records rendered dimensions, source dimensions, source origin, rotation, DPI, and the affine transform from source units to rendered pixels. The transform is `x' = a*x + c*y + e`, `y' = b*x + d*y + f`. Boxes use top-left rendered pixels. Missing boxes use page-only locations. Assembly keeps all original source blocks and all locations contributed by joined blocks. References, notes, tables, captions, equations, lists, code, and unclassified content remain explicit. Code is a supported block kind; its literal content, declared format and source locations survive extraction, assembly and export. Historical unclassified source blocks are not relabeled on read. Native table markup is content, not permission to execute HTML.

## Processing

PageCheck preserves the source wire contract of `fixes` and `joins`. Validation rejects unknown or wrong-page IDs, duplicate edits, blank deletion, edits to figures, backward joins or gaps containing substantive or unclassified content, reused join ends, and joins outside the context actually supplied. Adjacent join chains may span pages. A cross-page continuation may skip only native header/footer/page-number blocks classified in the extraction pageFurniture sidecar, with footer roles on the preceding page and header roles on the following page. All furniture survives separately at its original reading-order anchor. Canonical blocks retain increasing first-source anchors, every source exactly once, and only these explicitly permitted gaps within joined sources. Missing furniture provenance preserves the conservative adjacency rule. Heading and figure results are sidecars. They do not rewrite extraction IDs. A null heading decision demotes a false heading. PageCheck may propose joins involving heading candidates; assembly accepts them only after the heading decision resolves them as prose. Canonical `headingDecisions` retains the applied decisions. The correction and assembly owners apply edits and joins once. Table fixes retain their exact returned content and original format. Code does not compare corrected numbers, rows, columns, cells or spans with the source. Tables cannot join. A wrong model change to a number, row or cell reaches the reader.

Figure identity, asset availability, author caption, and generated description are independent. New Meta figures identify their rendered source-page region, PDF hash, verified PNG hash and dimensions, integer crop recipe and actual output dimensions. Optional provenance preserves historical unspecified metadata; its absence is no proof of native origin. Missing descriptions leave figures intact and require a located warning before successful publication. Source blocks remain available for reader and export accounting.

Provider receipts start before dispatch. Prepared receipts contain no provider-assigned ID. Completed receipts identify the saved response and its validation result. Unknown completion remains a distinct state. Extraction receipts retain provider/version and, for Meta extraction, the actual nested model configuration. New Meta extraction checkpoints cover every physical page with distinct accepted receipts in page order. Receipt page and figure IDs identify the processed unit. Failed runs retain stage and unit context.

Reports wrap original receipts with `performed` or `reused` delivery. Reuse keeps the original run, attempt ID, and usage. `validateReceiptReuse` compares owner, document, source, versions, target unit, and the full expected request fingerprint before reuse. The caller must decode the saved response and check its hash before applying it. `currentRunReceipts` excludes earlier-run reuse from current-run usage. A response replayed after a restart within its original run still belongs to that run's performed work; publication rejects a delivery label that disagrees with the receipt's immutable run ID. Usage and ambiguity counts remain unavailable when unmeasured. Recorded edits are not a factual-accuracy score. The dispatcher owns retry policy; these contracts never retry.

## Output and lifecycle

`OutputScope` fixes document, run, and revision IDs for canonical JSON, images, report, manifest, and rating. Required ZIP members are `normalized.txt`, `document.json`, `images.json`, and `processing-report.json`. Image files live under `images/`; an image-free document needs no directory entry. Archive assembly uses only validated manifest entries. Relative paths reject traversal, separators encoded as percent escapes, drive paths, and control characters.

Publication validation requires complete page and source-block coverage, valid locations, source-preserving joins, matching figure assets, matching output scopes, mandatory artifacts, and a matching terminal state. Every known unclassified source block needs an `unclassified-content` issue that names the block and retains its locations. Such output succeeds with issues. A blank document or missing page cannot succeed. Expiry and deletion are document lifecycle states, separate from run outcomes. Terminal runs do not restart; retry creates a new queued run. The storage owner must enforce transitions and uniqueness atomically.

## Product routes

The `productRoutes` registry declares request and response schemas, success status, and ownership policy. It includes session, one-PDF upload, document list/detail/status, retry, original and revision-scoped downloads, report, rating, and deletion. Upload metadata describes one multipart `file` field; handlers must inspect actual bytes and reject extra files. Session identity supplies ownership, never a request body. Sign-in and sign-out remain Better Auth-owned routes, not a second auth protocol.

Downloads use named artifact selectors and figure IDs, never client filesystem paths. Document status is read-only and cannot start work. Errors use the shared safe `ApiError` code/status mapping. Authorization, content sniffing, storage, byte streaming, rate limits, expiry enforcement, and HTTP handlers belong to later tasks.

## Verification

`pnpm exec vitest run tests/domain` checks round trips, JSON Schema generation, invalid IDs and coordinates, source coverage, joins, tables/references/notes, figures without descriptions, receipts, state transitions, manifest paths, and route inputs. `pnpm typecheck` checks the branded public types. Fixtures are deterministic synthetic data and require no credentials or paid calls. These checks establish contract behavior, not extraction quality or live route security.
