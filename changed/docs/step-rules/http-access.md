# Guarded HTTP entry

Covers: route:GET:/api/session, route:GET:/health, route:GET:/health/ready, route:GET:/auth/get-session, route:GET:/auth/sign-in-options, route:POST:/auth/sign-in/email, route:POST:/auth/sign-in/judge, route:POST:/auth/sign-out

1. `src/server/main.ts` is the only supported listener. Its outer Hono handler checks every request before dispatch to the public Mastra server factory. Mastra's built-in middleware cannot guard its earlier routes and deliberately skips framework-public routes. The factory still performs its normal license validation; no Mastra auth provider or enterprise feature is configured.
2. Public access is an exact method/path allowlist: GET `/`, `/sign-in`, valid `/documents/:documentId` shell paths, validated built app assets, `/health`, `/health/ready`, `/auth/get-session`, `/auth/sign-in-options`; POST `/auth/sign-in/email`, `/auth/sign-in/judge` and `/auth/sign-out`. The auth adapter returns 404 for `/auth/sign-in/judge` unless email-only sign-in is enabled. The shell contains no document content. Better Auth independently checks the selected auth endpoints, origins, cookies, and login limits. HEAD, OPTIONS, alternate encodings, old API prefixes, unknown paths, and unlisted auth endpoints gain no public exemption.
3. GET `/api/session` requires a valid server session and returns the shared Session schema. The exact document methods registered in `documentRouteDefinitions` also require a valid session: POST/GET `/api/documents`, GET `/api/documents/:documentId`, GET `/api/documents/:documentId/status`, and GET `/api/documents/:documentId/original`. Their handlers independently resolve the server session and enforce ownership. Dynamic IDs must match the shared opaque-ID shape without percent encoding. Every remaining request requires an admin session before route dispatch. Future product routes require a separately reviewed allowlist entry. Role/owner request fields and Mastra client headers confer no authority.
   An HTML GET/HEAD navigation to a denied Studio page receives the existing public product shell with its original 401/403 status. It offers sign-in or a route back to the dashboard. This does not load Studio content, APIs, or assets; those and control endpoints retain JSON denials.
4. The configured origin is explicit, and request authority must match it. Forwarded headers are not trusted. Non-auth mutations require the same Origin and reject cross-site Fetch Metadata. CORS is disabled. All responses carry no-sniff, no-referrer, frame denial, no browser feature delegation, and a CSP restricting embedding, objects, base URLs, and form targets. This baseline deliberately permits stock Studio scripts/styles; it does not claim full script-source isolation. Authenticated responses and errors are not cacheable. Only validated public hashed app assets use immutable caching.
5. Auth body intake has a five-second deadline and a 16 KiB cap; cancellation reaches its stream reader. Session lookup requests a five-second timeout, but the adapter waits for noncancelable Better Auth/database work to settle before releasing its connection. Therefore lookup latency and auth-runtime disposal do not have an unconditional five-second wall-clock bound. There are no retries here. Authentication failures return 503, absent/expired sessions 401, insufficient roles or rejected origins 403, and unknown authorized routes 404. Unexpected defects are logged and return a safe 500. Incoming cancellation propagates through the Effect runtime; it does not cancel SDK work that has already started.
6. Startup validates the port, required redacted auth secret, canonical origin, private data directory, Python executable path, and queue limit before binding loopback. `AMUSEME_HOST` is `127.0.0.1` (default) or `0.0.0.0` for a container platform. The origin is a loopback HTTP origin whose port equals `AMUSEME_PORT`, or an HTTPS origin served by a TLS-terminating proxy (Modal). For an HTTPS origin, the gateway rewrites an incoming plain-HTTP request to that origin only when its Host equals the configured host; other hosts keep their HTTP URL and fail the origin check. Forwarded headers still have no authority. The listener itself speaks plain HTTP; the proxy must be the only network path to it. The private directory is mode 0700 and SQLite files mode 0600; auth, application, and Mastra databases live there, outside all static roots. `AMUSEME_APP_DIR` can select the local watched build for development; production defaults to `.mastra/output/app`. `AMUSEME_PYTHON_BIN` defaults to the absolute local `data/python/.venv/bin/python` path. `AMUSEME_QUEUE_LIMIT` defaults to 10 and must be between 1 and 1000. Live upload admission requires validated processing configuration and an available provider guard policy; otherwise admission is disabled. No environment flag enables fixture admission. The only Mastra singleton is in `src/mastra/index.ts`; `makeAmuseMe` is pure and inspectable without credentials or I/O.
7. One ManagedRuntime composes authentication, private document/artifact storage, PDF inspection/rendering, provider guards, processing stages, dispatch, and document/output handlers. A scope owns that runtime, persistent Mastra storage, workers, and the Node listener. After storage initializes, register Mastra cleanup before attaching storage and local observability, replacing placeholder agents/workflow with their runtime-bound instances, and starting workers. Workers start once before readiness. Scope exit cancels and awaits processing/maintenance fibers, then stops readiness/admission and drains HTTP for at most five seconds before force-closing remaining connections. Mastra cleanup allows five seconds to stop workers and one second to flush traces, then always attempts shutdown within one second, including after failure. The outer storage finalizer and runtime disposal follow; startup failures also release acquired resources. SDK calls cannot be aborted by these deadlines, so late writes and runtime disposal can extend total shutdown; there is no whole-process deadline or guaranteed trace delivery after a flush timeout. See [observability and retention](observability-retention.md) for the installed SDK shutdown-order workaround and persistence regression.
8. Production builds use Vite's SSR bundle for the guarded entry and the CLI's unmodified Studio assets via `MASTRA_STUDIO_PATH`. Do not run the generated CLI listener. Compatibility checks exercise actual factory routes, roles, spoofing, methods, assets, startup, and termination without paid inference. The manager verifies stock Studio in Chrome.
